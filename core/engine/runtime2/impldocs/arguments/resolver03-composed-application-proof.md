# Argument for [resolver03-composed-application-proof]

`tla/ResolverApplication.tla` gives every resolver-output observation one work item and one deterministic resolver function over the materialized object-fragment prefix. `tla/MaterializationProof.tla` proves that dependency-first prefix materialization equals final-result materialization, and `tla/ResolverApplicationProof.tla` therefore proves that applying the same resolver function to either input yields the same raw observation. Projection coverage remains an explicit premise at this shared layer rather than being hidden in the returned-result world. Nonempty resolver Query fragments and their independent Query OERs are outside this calculus.

`tla/Resolver03Projection.tla` connects each result observation to one exact direct or guarded nested requirement token. The exact registry-extension assumptions imply that every such token is in the producer's supplied demand, so `Resolver03ProjectionProof.tla` derives the projection-coverage premise. `tla/Resolver03ApplicationProof.tla` composes that fact with product-fold termination, materialization stability, projection semantics, fragment and resolver-demand closure, and the resolver-output typename contract to prove `Resolver03ApplicationsAreCorrect`.

This is a symbolic proof of the finite extensional construction calculus, not yet a structural refinement theorem for the Kotlin function. The world assumes faithful extraction of exact guarded requirement tokens, result observations, resolver functions, materialized inputs, and returned cells from Kotlin selections and values. TLC checks a concrete composed instance with one guarded nested requirement and reaches the correct terminal result in a 27-state model, but that finite run does not discharge those extraction assumptions.
