Examples 1 to 4 of 13: nested fields, aliases, overlapping parents and argument values.

Example 1 / 13

A nested field becomes a tree

The baseline: field members carry their own child forests.

The operation contributes one Query.user member and two child members. The schema default provides id = "u1" even though the operation does not spell it out. With no overlap or conditions, merging either level leaves these observed fields unchanged.

Schema · Example 01GRAPHQL

type Query {
  user(id: ID = "u1"): User
  node(id: ID = "n1"): Node
}
interface Node {
  id: ID
  label: String
}
type User implements Node {
  id: ID
  label: String
  name: String
  friend: Node
}
type Team implements Node {
  id: ID
  label: String
  title: String
}

Operation · Example 01GRAPHQL

{ user { id name } }
Example 2 / 13

Two aliases, one construction key

Response identity and construction identity diverge.

left and right name two response positions. The parsed construction forest has two Query.user contributions with the same arguments and no alias metadata. Merging at Query gives one parent whose child forest still contains both id contributions. Merging those children at User leaves one id key.

Example 3 / 13

Overlapping parents accumulate different children

A merge normalizes one object level at a time.

The first user contribution contributes id; the second contributes id and name. The diagrams sort members, so the second contribution appears first. Their equal construction keys merge at Query, but the child forests concatenate to id, id, name. A separate merge at User produces the two distinct child keys.

Example 4 / 13

Arguments decide which parents can merge

Defaults, null, and coercion change key identity.

The same operation has four aliased user contributions. The first uses the schema argument default, the second uses $id, the third spells out "u1", and the fourth spells out "u2". Choose request variables to see which fully resolved argument values (ground tuples) become equal. All four variants have no unresolved operation variables after decoding.
