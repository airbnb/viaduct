# Argument for `resolver-provider-containment-construction`

This claim concerns the pre-reasoning Kotlin fixture and registry construction boundary, not semantic variable execution. Every canonical `FieldValueResolver` has one fixed open parent-object fragment; its optional Query-rooted fragment is outside this object-provider claim. Node-valued source fields retain their coordinates and arguments, while the built-in `Query.node` dispatcher has an empty object fragment; genuine field-relative variables on a source resolver are therefore constructed against the unchanged canonical producer coordinate.

Pre-reasoning composition resolves each provider's response-key path against its alias-preserving object-fragment source, rejects lossy type conditions and ambiguous canonical occurrences, and emits an alias-free key path. `resolverRegistryOf` requires that path to match an occurrence path in its defining resolver's fixed fragment with exact keys. Registry extension consequently traverses one defining envelope and no longer computes or roots a separate `extendedVariables` fragment. The arbitrary generator explicitly inserts every chosen aliased provider path into that envelope before emitting its variable use, then invokes the same compiler used by static fixtures.

Focused `FromObjectFieldTest` and `ResolverDemandTest` cases reject absent, wrongly rooted, lossy, and canonically ambiguous provider paths, along with variable and resolver dependency cycles. `SharedBranchDependenciesTest` accepts acyclic provider paths whose production and use share structural branches, including argument-distinct occurrences, and rejects true shared-branch cycles and variables used in their own provider-path arguments on both input roots. Generator tests require shared-branch providers and consumers, variables on shared branch-field arguments, and independent flows in both directions between branches on both input roots, validating every sampled registry through canonical assembly. Generated variable dependencies follow binding creation order: fresh provider paths start with literal arguments, and later bindings can replace those literals in earlier paths. This preserves acyclic inputs independently of registry validation without imposing a structural branch order. Resolution consumes the compiled provider metadata through occurrence-local bindings; the shared `FromFieldVariablesContract` verifies shared-branch execution, parent traversal, and variables on branch-field arguments against both engines within a bounded timeout.
