# Release 3.0.0

See [GitHub Release](https://github.com/airbnb/viaduct/releases/tag/v3.0.0).

Viaduct 3.0.0 is a major release. The headline work is **schema scopes declared in `scopes.yaml` and validated at build time**, **one `ctx.ref(...)` entry point for node and root-field references**, a **soft-by-default GraphQL Representational Type (GRT) getters**, a **Java Tenant API (beta release)**, and **Java 25 support**. It also includes early work on a new execution engine and `@defer` incremental delivery, both off by default.

Three changes affect every consumer's build regardless of what else they use:

- the Viaduct Gradle plugins now require **Kotlin 2.2 or 2.3**;
- tenant modules must be **rebuilt with the 3.0 plugins**;
- GRT getters **`getX()` now returns `null` on a data failure** instead of throwing.

<!-- more -->

Start with Requirements and Breaking Changes below.

## Requirements

- **Java:** 17 is the new minimum (support for Java 11 has been dropped), and the published bytecode still targets Java 17. Viaduct 3.0 is built and tested on Java 17, 21 and 25.
- **Kotlin:** the Viaduct Gradle plugins require **Kotlin 2.2 or 2.3**.  Building for Java 25 needs Kotlin 2.3. Use a KSP2 release that matches your Kotlin version (KSP 2.3 uses standalone versions such as `2.3.7`).
- **Gradle:** 8.11 or newer; CI tests builds on 8.11 and 9.1. Java 25 needs Gradle 9.1 or newer.

## Breaking Changes

### Build and bootstrap — affects every consumer

- **The Viaduct Gradle plugins require Kotlin 2.2 or 2.3** ([16653620b](https://github.com/airbnb/viaduct/commit/16653620b)) by @gokhan-ozgozen — Viaduct itself now builds with Kotlin 2.3.21, KSP 2.3.7 and Gradle 9.1. This commit carries no `!`, but it is the change most likely to break a consumer build. See Requirements.
- **Rebuild every tenant module with the 3.0 plugins.** Module configs generated by 2.0 fail at startup:
  - every field and node entry must now carry `tenantMetadata` ([1a50aec92](https://github.com/airbnb/viaduct/commit/1a50aec92), [9b686122c](https://github.com/airbnb/viaduct/commit/9b686122c)) by @pclowes;
  - every config must declare an `apiName`, and two configs with the same `<tenantName, apiName>` are rejected ([9ffd1fd5c](https://github.com/airbnb/viaduct/commit/9ffd1fd5c)) by @kristileka;
  - a config file whose `version` is not `1` is rejected ([0ea77aa07](https://github.com/airbnb/viaduct/commit/0ea77aa07)) by @kristileka.
- **Schema scopes are declared in `src/main/viaduct/scopes.yaml`; the `viaductApplication { declareScoping { } }` DSL is removed** ([ad8aa6c09](https://github.com/airbnb/viaduct/commit/ad8aa6c09)) by @geovannefduarte — move the DSL contents into `scopes.yaml` with `version: 1`. Multi-document YAML, YAML aliases and empty named scope sets are rejected. `SchemaScopingBuilder` and the `SCHEMA_SCOPES_DECLARED_TWICE` / `SCHEMA_SCOPING_DECLARED_TWICE` error codes are gone.
- **Schema files and module configs are loaded from build-generated resource indexes** ([7e8bd1805](https://github.com/airbnb/viaduct/commit/7e8bd1805), [9e18ace23](https://github.com/airbnb/viaduct/commit/9e18ace23)) by @pclowes — the application plugin writes `META-INF/viaduct/indexes/*.index`, and the runtime loads only the resources listed there. Each indexed resource must appear exactly once on the classpath, and duplicate module-config contributors fail the build. Standard plugin layouts need no change. `.graphqls` files or module JSON added to the classpath outside the build must move into it. A missing index fails startup with an actionable error; there is no classpath-scan fallback. Supply schemas and module configs through the generated indexes, or pass them explicitly.

### Stricter build-time validation

Each of these fails a build that 2.0 accepted:

- Type-level `@resolver` on an object type that doesn't implement `Node` (`RESOLVER_ON_NON_NODE_OBJECT`) ([20eee5ecb](https://github.com/airbnb/viaduct/commit/20eee5ecb)) by @gokhan-ozgozen;
- `@namespaceType` on a type that also declares `@connection` or `@edge` (`NAMESPACE_TYPE_HAS_CONFLICTING_DIRECTIVE`) ([a169f2bb1](https://github.com/airbnb/viaduct/commit/a169f2bb1)) by @alexanderuv;
- Two fields whose generated accessors collide, such as `foo` and `fooOrThrow` ([527bad796](https://github.com/airbnb/viaduct/commit/527bad796)) by @geovannefduarte;
- A `@Resolver` class that doesn't extend exactly one generated resolver base. Indirect inheritance through an intermediate class is now allowed ([85d2e3e15](https://github.com/airbnb/viaduct/commit/85d2e3e15)) by @catacraciun;
- **Required selection sets are disallowed on mutation resolvers** ([9755643c5](https://github.com/airbnb/viaduct/commit/9755643c5)) by @alexanderuv — mutation resolvers on the mutation root or on a reachable `@namespaceType` can't declare `objectValueFragment` or `queryValueFragment`. Call `ctx.query()` or `ctx.mutation()` inside `resolve` instead;
- A variable used inside a nested named fragment of a required selection set must be bound; otherwise bootstrap fails with `UnboundVariablesException` ([9a8e6f522](https://github.com/airbnb/viaduct/commit/9a8e6f522)) by @catacraciun;
- **A required selection set can't use a from-field variable in a `@skip` or `@include` condition** ([980b8b895](https://github.com/airbnb/viaduct/commit/980b8b895)) by @alexanderuv — a variable bound with `fromObjectField` or `fromQueryField` in the `if` argument fails bootstrap with `InvalidVariableException`. Select the value in the fragment and fetch the conditional data with `ctx.query()` instead. Variables bound with `fromArgument` or a variables provider still work;
- A required selection set that applies a directive to a `@parent` field, or to an inline fragment or fragment spread that directly contains one, or that uses a variable anywhere beneath a `@parent` field ([49a9cab0b](https://github.com/airbnb/viaduct/commit/49a9cab0b)) by @alexanderuv;
- With `scopes.yaml`, an `@scope(to:)` name that isn't declared, or a declared scope set that produces an invalid schema ([a324dedab](https://github.com/airbnb/viaduct/commit/a324dedab)) by @geovannefduarte;
- Invalid `@scope` on type extensions that add no fields ([922c023ef](https://github.com/airbnb/viaduct/commit/922c023ef)) by @geovannefduarte.

### Generated types (GRTs) — Kotlin and Java

- **The bare accessor `getX()` now returns `null` instead of throwing** ([f137387b2](https://github.com/airbnb/viaduct/commit/f137387b2)) by @geovannefduarte — `getX()` is now the soft accessor, and `getXOrThrow()` is the strict one. Non-null `Boolean!`/`Int!`/`Float!` fields now return the nullable boxed type, so Kotlin call sites that use the value in arithmetic or boolean contexts stop compiling, and code compiled against 2.0 fails with `NoSuchMethodError`. Call sites that need the old behavior must switch to `getXOrThrow()`. Call sites on already-nullable schema fields keep compiling but change behavior silently, so audit them by hand. Java GRTs follow the same model: `getAmount()` returns `Double`, and `getAmountOrThrow()` returns `double`.
- **The `getXOrNull()` accessor form is removed from Kotlin GRTs** ([ba1a21601](https://github.com/airbnb/viaduct/commit/ba1a21601)) by @geovannefduarte — rename call sites to `getX()`, which has the same soft behavior in 3.0. The API dump doesn't show this, because schema-specific generated classes aren't in it.
- **Java GRT reads now match Kotlin semantics** ([9d5b9ab42](https://github.com/airbnb/viaduct/commit/9d5b9ab42)) by @catacraciun — reading an unselected or unset field raises `UnsetFieldException` instead of returning `null`. A `null` on a non-null field, and malformed list or object values, raise `TenantUsageException`.
- **Java GRT builders validate values** ([f4d90838a](https://github.com/airbnb/viaduct/commit/f4d90838a), [480a7663c](https://github.com/airbnb/viaduct/commit/480a7663c)) by @catacraciun:
  - a setter that receives a wrong scalar class, an invalid enum value, a GlobalID for the wrong type, or a `null` for a non-null field throws `TenantUsageException`;
  - `build()` throws for missing required fields and `@oneOf` violations;
  - list values are stored as unmodifiable copies.
- **Java resolvers for `@idOf` and Node ID fields return `GlobalID<T>` instead of `String`** ([d940dd53f](https://github.com/airbnb/viaduct/commit/d940dd53f)) by @catacraciun
- **Java object GRTs no longer generate a `Fields.<field>` constant for `@backingData` fields** ([930382ac8](https://github.com/airbnb/viaduct/commit/930382ac8)) by @catacraciun — read backing data with `ObjectBase.get("field", Backing.class)`.

### Tenant API — resolver context

- **`nodeRef` is now `ref`** ([e128ccc48](https://github.com/airbnb/viaduct/commit/e128ccc48), [4ec3666ff](https://github.com/airbnb/viaduct/commit/4ec3666ff)) by @alexanderuv — `ResolverExecutionContext.nodeRef(GlobalID)` and the Kotlin `nodeRef(localId: String)` extension are removed in both the Kotlin and Java APIs. Call `ctx.ref(...)` with the same arguments.
- **`rootFieldRef` is replaced by `ctx.ref` with a generated root field call** ([bc4a879d9](https://github.com/airbnb/viaduct/commit/bc4a879d9), [6ca3d04b9](https://github.com/airbnb/viaduct/commit/6ca3d04b9)) by @alexanderuv — for example, Kotlin `ctx.rootFieldRef(Query.Fields.product, args)` becomes `ctx.ref(Query.product { ... })`. `RootFieldCall.resolve` is replaced by `field()` and `arguments(context)`, so hand-written `RootFieldCall` implementations must be updated.
- **The string-based `query(String, …)` and `mutation(String, …)` overloads are removed from the Kotlin API** ([bcbf4a12e](https://github.com/airbnb/viaduct/commit/bcbf4a12e)) by @kristileka — use `query(QueryFromAnnotation, …)` and `mutation(MutationFromAnnotation, …)`.
- **Mutation contexts no longer expose query or object values:**
  - Kotlin mutation contexts lose `getQueryValue()` ([a46dc0792](https://github.com/airbnb/viaduct/commit/a46dc0792)) by @alexanderuv;
  - the Java `MutationFieldExecutionContext` no longer extends `FieldExecutionContext` ([e6dcb1e14](https://github.com/airbnb/viaduct/commit/e6dcb1e14)) by @alexanderuv.

  Read data with `ctx.query(...)` inside `resolve`.
- **In the Java API, `ctx.mutation()` works only in mutation field resolvers** ([a7787b34e](https://github.com/airbnb/viaduct/commit/a7787b34e)) by @catacraciun — calling it from a query, node or object-field resolver throws `TenantUsageException`.
- **`ResolverExecutionContext.selectionsFor(type, selections, variables)` is removed** ([9139e4ed4](https://github.com/airbnb/viaduct/commit/9139e4ed4)) by @amity177 — declare reads as resolver dependencies, or use named operations.
- **The selection-construction surface of `SelectionSet` is removed** ([a6c0aaa2a](https://github.com/airbnb/viaduct/commit/a6c0aaa2a), [4116a184d](https://github.com/airbnb/viaduct/commit/4116a184d), [de300569b](https://github.com/airbnb/viaduct/commit/de300569b), [8f2ce9602](https://github.com/airbnb/viaduct/commit/8f2ce9602), [c69d773c7](https://github.com/airbnb/viaduct/commit/c69d773c7)) by @amity177:
  - removed: `SelectionSet.type`, `isEmpty()`, `selectionSetFor(Type)` and `toFragment()`, plus the `OutputSelectionFragment` class;
  - a custom `SelectionSet` passed to framework batching must implement `InternalSelectionSet`.
- **New abstract members for code that implements tenant API interfaces itself, such as test fakes:**
  - `SelectionSet.selectedFieldCoordinates()` ([c3f681279](https://github.com/airbnb/viaduct/commit/c3f681279)) by @alexanderuv;
  - `SelectiveNodeExecutionContext.ownedSelections()` ([afe33183d](https://github.com/airbnb/viaduct/commit/afe33183d)) by @fireboy1919.
- **`isPresent(field)` is now `true` for an omitted input field that has a schema default** ([2731f3c88](https://github.com/airbnb/viaduct/commit/2731f3c88)) by @catacraciun — Java input getters also return the schema default. Code that used `isPresent` to tell a client-sent value from an applied default must compare against the default instead.
- **Input getters and argument wrappers return programmatic defaults** ([cdfc33bbd](https://github.com/airbnb/viaduct/commit/cdfc33bbd)) by @catacraciun — in 2.0 they threw or dropped the default.
- **`viaduct.api.fetchOrNull` and `fetchOrDefault` are now `@InternalApi`** ([b28ba31e1](https://github.com/airbnb/viaduct/commit/b28ba31e1)) by @catacraciun — Kotlin callers get an opt-in warning, which `-Werror` turns into an error.
- **Selective resolvers are temporarily disabled in the Java tenant API** ([8d6e7c90b](https://github.com/airbnb/viaduct/commit/8d6e7c90b)) by @catacraciun — `@resolver(isSelective: true)` on a Java-resolved field or node fails codegen and bootstrap. Remove it, or keep those resolvers in Kotlin.

### Service API

## Features

### Schema scopes

- Scopes are declared in `scopes.yaml`, and every declared scoped schema is built and validated during the build, with all failures reported at once ([ad8aa6c09](https://github.com/airbnb/viaduct/commit/ad8aa6c09), [a324dedab](https://github.com/airbnb/viaduct/commit/a324dedab)) by @geovannefduarte.
- The build hands the declared scopes to the runtime as a manifest, and `SchemaScopeInfo.fromResources()` returns them ([93ac16f77](https://github.com/airbnb/viaduct/commit/93ac16f77)) by @geovannefduarte.

### Java tenant API

- **Stability annotations:** every public Java API type carries `@StableApi`, `@ExperimentalApi` or `@InternalApi` ([c8a0913bf](https://github.com/airbnb/viaduct/commit/c8a0913bf)) by @catacraciun, and the stable surface is checked for binary compatibility ([#436](https://github.com/airbnb/viaduct/pull/436)) by @geovannefduarte.
- **Location:** the implementation moved from `core/x/javaapi` to `core/javaapi` ([70423b54b](https://github.com/airbnb/viaduct/commit/70423b54b)) by @catacraciun. Packages and published coordinates are unchanged. The API reference moved from `/apis/x-javaapi-api/` to `/apis/javaapi-api/`.
- **Generated types now match Kotlin:** Java GRTs generate the same accessors as Kotlin ([9d5b9ab42](https://github.com/airbnb/viaduct/commit/9d5b9ab42)), `toBuilder()` on object and input GRTs ([cd4028da2](https://github.com/airbnb/viaduct/commit/cd4028da2)), and dynamic `@backingData` reads ([930382ac8](https://github.com/airbnb/viaduct/commit/930382ac8)). Code generation honors custom root type names ([8f45c84e3](https://github.com/airbnb/viaduct/commit/8f45c84e3)). All by @catacraciun.
- **Resolver features:**
  - field batch resolvers can return a per-item value, null or error through `batchResolveWithErrors` ([87f886c8e](https://github.com/airbnb/viaduct/commit/87f886c8e));
  - typed `GlobalID<T>` for ID fields ([d940dd53f](https://github.com/airbnb/viaduct/commit/d940dd53f));
  - `@TenantBootstrapper` support ([97025acd1](https://github.com/airbnb/viaduct/commit/97025acd1));
  - non-blocking `fetchOrNull` / `fetchOrDefault` helpers ([b28ba31e1](https://github.com/airbnb/viaduct/commit/b28ba31e1)).

  All by @catacraciun.
- **Gradle:** the `module-java` plugin runs the Java registry annotation processor and packages the module config, so Java modules bootstrap without classpath scanning ([6345cc115](https://github.com/airbnb/viaduct/commit/6345cc115)) by @kristileka.
- **Demo:** a standalone Java demo application, `demoapps/starwars-java` ([4e05cd91b](https://github.com/airbnb/viaduct/commit/4e05cd91b)) by @catacraciun.

### Resolver context and references

- `ctx.ref(...)` is the single entry point for lazy references to nodes and root fields:
  - `ctx.ref(GlobalID)` and `ctx.ref(localNodeId)` ([d9828a499](https://github.com/airbnb/viaduct/commit/d9828a499)) by @alexanderuv;
  - generated `RootFieldCall` factories on the root query type and every eligible namespace field ([4ca5b19ae](https://github.com/airbnb/viaduct/commit/4ca5b19ae), [23b0a3d14](https://github.com/airbnb/viaduct/commit/23b0a3d14)) by @alexanderuv.
- Field resolver contexts expose the calling resolver as `caller`. It is informational and must not be used for authorization ([ba07c27e2](https://github.com/airbnb/viaduct/commit/ba07c27e2)) by @alexanderuv.
- Generated types add `getXOrThrow()` next to `getX()` ([527bad796](https://github.com/airbnb/viaduct/commit/527bad796)) by @geovannefduarte.
- `ReferenceSpy` asserts the references a resolver creates ([e5906d370](https://github.com/airbnb/viaduct/commit/e5906d370)) by @alexanderuv, and the mock harness supports `@GraphQLOperation` queries and mutations ([ae6da2a78](https://github.com/airbnb/viaduct/commit/ae6da2a78)) by @kristileka.

- Viaduct builds with Kotlin 2.3.21, KSP 2.3.7 and Gradle 9.1 ([16653620b](https://github.com/airbnb/viaduct/commit/16653620b), [00230ca63](https://github.com/airbnb/viaduct/commit/00230ca63)) by @gokhan-ozgozen.

- New `com.airbnb.viaduct.gradle:metamodule` library, applied by the module plugins ([b5b5115b7](https://github.com/airbnb/viaduct/commit/b5b5115b7), [a94251ea3](https://github.com/airbnb/viaduct/commit/a94251ea3)) by @gokhan-ozgozen:

### Schema and engine
